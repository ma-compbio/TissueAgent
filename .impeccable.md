# TissueAgent — Design Context

## Users

TissueAgent serves **three audiences simultaneously**:

1. **Computational biologists / bioinformaticians** running spatial transcriptomics analyses on their own datasets. Mid-day focused sessions, often hours long. They care about clarity, audit trails, and reproducibility.
2. **Wet-lab biologists** who outsource compute. Less Python-fluent; want confidence and reassurance, not internals.
3. **ML / agent-systems researchers** building on top of the framework. They care about prompts, traces, and what the agent decided and why.

The UI should serve the most-skilled user but stay legible to a wet-lab biologist running their first analysis. Don't amputate functionality for the novice; don't bury it from the expert.

**Context of use**: alongside paper PDFs, terminals, notebooks, and `.h5ad` files. Sessions are deliberate and analytical — never tap-and-swipe consumer interactions.

## Brand Personality

Three words: **calm, scientific, precise**.

This is a *lab instrument*, not an AI chatbot. Reminiscent of Leica microscope software, Igor Pro, Prism, well-built scientific tools — quiet authority earned through every interaction making sense. Restrained color, intentional typography, rhythm and hierarchy in spacing.

Explicitly NOT:
- The "AI tool" aesthetic (cyan-on-purple, glowing gradients, glassmorphism, neon).
- ChatGPT-style chat-as-everything interfaces.
- Notion-style soft pastel friendliness — too consumer for a research tool.
- Linear-style "we are a startup" minimalism. We have actual content to display.

Emotional goals: confidence ("I can trust this"), legibility ("I always know what's happening"), respect for the user's expertise.

## Aesthetic Direction

**Theme**: light primary, with a dark mode toggle (already wired). Light reads better in mixed-document workflows where the user is moving between TissueAgent, a PDF, and their notebook. Dark mode accommodates evening / dim-room sessions.

**Typography**: pair a refined sans for UI with a precise mono for data (paths, agent IDs, parameters). Body should feel like reading a technical document, not a chat app. Display font should NOT be one of the "AI defaults" (Inter, DM Sans, Outfit, Plus Jakarta, Instrument). Reach for something with more personality and discipline.

**Color**: a calm neutral foundation with one sharp accent reserved for the live/pause states. Use OKLCH. Tint neutrals toward the accent hue. The 60-30-10 rule: 60% surface, 30% secondary, 10% accent — and the accent only appears when something genuinely needs attention.

**The differentiating moment**: when copilot pauses for review, the UI should make it impossible to miss without being garish. The current banner is a step in the right direction; it can be sharper, more deliberate, more like a lab safety indicator than a notification.

## Design Principles

1. **The pipeline is the protagonist.** The five-stage agent flow (Planner → Recruiter → Manager → Evaluator → Reporter) and the evolving plan are the soul of the product. Every other element defers to making those legible. The current pipeline stepper is on the right track but underdesigned.

2. **Color earns its place.** Status colors should mean something (running, paused-for-review, done, failed). Decorative color is forbidden. A neutral interface with a single intentional accent reads more authoritative than a rainbow palette.

3. **Density is a feature.** Researchers want to see plan + chat + pipeline at once. Don't pad everything out to feel "spacious" — use measured 4pt-scale spacing and let information sit close. Type hierarchy carries the load.

4. **Review moments are ceremonial.** When the copilot pauses, the UI transforms. The user shouldn't have to scan to find what's expected of them. This is the one place where the design *can* be loud.

5. **Provenance is visible, not buried.** Where a plan came from (template vs. de novo), who edited it, what parameters were used — these are first-class citizens, not footnotes. Don't hide them in collapsible sections by default.

6. **Avoid the AI fingerprint.** No glassmorphism, no gradient text, no neon-on-dark, no cyan-purple accents, no border-left status stripes, no rounded-square icons above every heading. If a Stripe / OpenAI / Cursor designer would recognize the pattern, don't use it.
